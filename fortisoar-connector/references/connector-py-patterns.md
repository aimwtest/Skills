# connector.py / operations.py patterns

How to write the Python side of a connector. The skeleton in
`assets/connector-skeleton/` already implements the recommended pattern — this file

## Dispatch patterns

FortiSOAR's `execute()` receives an `operation` string and must route it to a
function. Three patterns exist in the wild:

1. **Hand-written dict-dispatch in `operations.py`** — an `operations = {...}` dict
   maps operation names to functions; `connector.py` does `operations.get(op)(config, params)`.
   **This is the default.** All 5 reference Fortinet repos use it. Prefer it.
2. **Wizard-autogenerated `builtins.py`** — the FortiSOAR Connector Wizard generates a
   `builtins.py` with `supported_operations = {...}` and a `# FSR Autogenerated Content.
   DO NOT DELETE` banner. Only touch this if the user pastes in Wizard-generated code;
   don't create it from scratch.
3. **Raw `if/elif` in `execute`** — works, but doesn't scale past a few operations.
   Avoid for new code.

## connector.py

Thin dispatcher. One class extending `Connector`, implementing `execute` and
`check_health`. Keep business logic out of it.

```python
from connectors.core.connector import Connector, get_logger, ConnectorError
from .operations import operations, check_health
from .constants import LOGGER_NAME

logger = get_logger(LOGGER_NAME)


class SampleConnector(Connector):
    def execute(self, config, operation, params, *args, **kwargs):
        try:
            action = operations.get(operation)
            if action is None:
                raise ConnectorError("Unsupported operation: {}".format(operation))
            return action(config, params)
        except ConnectorError:
            raise
        except Exception as err:
            logger.exception("Operation '%s' failed: %s", operation, err)
            raise ConnectorError("Operation '{}' failed: {}".format(operation, err))

    def check_health(self, config):
        check_health(config)
```

- Re-raise `ConnectorError` untouched, wrap everything else — this keeps your explicit
  error messages intact while still catching surprises.
- `check_health` should raise `ConnectorError` on failure and return normally on
  success. FortiSOAR shows a green/red health indicator based on it.

## operations.py

Holds the business logic: a `_request` helper, one function per operation with
signature `(config, params) -> dict`, `check_health(config)`, and the `operations`
dict.

```python
import requests
from connectors.core.connector import get_logger, ConnectorError
from .constants import LOGGER_NAME, DEFAULT_TIMEOUT

logger = get_logger(LOGGER_NAME)


def _request(config, method, path, params=None, json_body=None):
    base_url = (config.get("base_url") or "").rstrip("/")
    url = "{}/{}".format(base_url, path.lstrip("/"))
    verify = bool(config.get("verify_ssl", True))
    try:
        r = requests.request(method, url, headers=_headers(config),
                             params=params, json=json_body,
                             verify=verify, timeout=DEFAULT_TIMEOUT)
    except requests.exceptions.RequestException as err:
        raise ConnectorError("Request to {} failed: {}".format(url, err))
    if not r.ok:
        raise ConnectorError("API error {}: {}".format(r.status_code, r.text))
    return r.json() if (r.text and r.text.strip()) else {}


def get_alerts(config, params):
    return _request(config, "GET", "alerts", params={"start": params.get("start_time")})


def check_health(config):
    _request(config, "GET", "status")
    return True


operations = {
    "get_alerts": get_alerts,
}
```

**The `operations` dict keys must exactly match the `operation` names in `info.json`.**
A mismatch produces "Unsupported operation" at runtime.

`params` is what the playbook step passes for that action. Note FortiSOAR sometimes
sends `params` as `[]` (empty list) when an action has no inputs — if you index into
it, guard with `params = params if isinstance(params, dict) else {}`.

## Auth snippets

Auth varies per target API and must come from the user's answer, not a default. Build
it in a `_headers(config)` helper (or pass `auth=`/a token to `requests`):

**API key header** (skeleton default):
```python
def _headers(config):
    return {"Authorization": "Bearer {}".format(config.get("api_key", "")),
            "Content-Type": "application/json"}
# or a custom header: {"X-API-Key": config.get("api_key", "")}
```

**Basic auth** — don't build a header, pass `auth`:
```python
r = requests.request(method, url,
                     auth=(config.get("username"), config.get("password")),
                     verify=verify, timeout=DEFAULT_TIMEOUT)
```

**OAuth2 client-credentials** — fetch a token first, then send it as Bearer:
```python
def _get_token(config):
    resp = requests.post(config["token_url"], data={
        "grant_type": "client_credentials",
        "client_id": config["client_id"],
        "client_secret": config["client_secret"],
    }, timeout=DEFAULT_TIMEOUT)
    resp.raise_for_status()
    return resp.json()["access_token"]
```
(For OAuth2 you'd add `client_id`/`client_secret`/`token_url` as config fields.)

**Client certificate** — pass `cert=` to `requests`:
```python
r = requests.request(method, url, cert=(config["cert_path"], config["key_path"]),
                     verify=verify, timeout=DEFAULT_TIMEOUT)
```

## constants.py and error_handler.py

- **`constants.py`** (recommended): logger name, default timeout, base-URL templates,
  mapping tables (e.g. UI-label → API-value), and reusable error-message strings.
  Keeps magic values out of `operations.py`.
- **`error_handler.py`** (optional): only worth adding once the target API has enough
  distinct error shapes that a central `handle_exception(err)` earns its keep. Don't
  add it by default — inline `ConnectorError` raising is fine for simple connectors.

## Resilience

These small habits prevent the most common runtime ("dynamic") failures — see
`troubleshooting.md`:

- **Validate before `.json()`.** A non-2xx or empty/HTML body will make `.json()`
  raise `Expecting ',' delimiter or '}'`-style errors. Check `response.ok` and that
  the body is non-empty first.
- **Handle non-2xx explicitly** with a `ConnectorError` that includes the status code
  and the API's error message — this is what shows up in the playbook Error Output.
- **Always set `timeout=`** on requests so a hung upstream doesn't hang the connector.
- **Honor `verify_ssl`** from config rather than hardcoding `verify=True/False`.
